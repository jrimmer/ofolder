# Design and implementation review, 2026-11-03

Scope: the whole of ofolder as of commit `f1f13f8` plus the guard setting. Method: reading the code for
the places where untrusted text meets a privileged action, measuring the release build on the real
desktop, and the failures the end-to-end suite has produced (see `docs/e2e.md`). Each finding says what
was observed and how, then what to do. "Verified" means checked by running or reading it today; anything
else is marked as an inference.

## What is already sound

- **Injection into Hyprland and the shell.** Rule names and classes must be plain identifiers; the program
  path in a key binding must be absolute with no quotes, backslashes or control characters; bind text that
  could end a Lua string is refused; window addresses are checked (`0x...`); commands are built without a
  shell; ffmpeg gets its input as `file:<path>` so a name like `-i` or `http:` cannot become an option or a
  protocol. All covered by tests (verified in `core/hypr.rs`, `core/keybind.rs`, `adapters/hyprctl.rs`,
  `strip/preview.rs`).
- **The control socket.** One socket per strip in a `0700` runtime folder, mode `0600`, a fixed allowlist of
  command ids, a 200 ms read timeout and a size cap (verified in `app/keys.rs`).
- **Fails loud, never guesses.** A folder that cannot be read is "unknown", a goto is refused unless the path
  bar is verified open, keys are sent only to a verified window, a failed move is shown to the user.
- **No network code** in the workspace (verified by search). Memory-safe: 6 `unsafe` uses, all small libc calls.
- **Pinned and locked**: gpui 0.2.2, libc 0.2.186, `--locked`.

## Findings, in the order I would act on them

### 1. Subprocess calls with no time limit (durability, high value, small)

Every conversation with the compositor forks `hyprctl` through `.output()` (`adapters/hyprctl.rs:24`) with no
time limit; `wtype` uses `.status()` and `wl-copy` is waited on with `child.wait()` **on the UI thread**
(`app/strip_cmd.rs:718`). Only the picker IPC has a cap (800 ms). If Hyprland or one of these programs wedges,
the calling thread blocks forever: the docking thread stops following the dialog, a poll stops, or the rails
freeze. The slow `wl-copy` was already seen once to make the rails sluggish (it ran `xdg-mime`; fixed by naming
the type).
**Do:** one shared helper that runs a command with a deadline and kills it (the picker IPC already has the code),
used for `hyprctl`, `wtype`, `wl-copy`, `systemctl`; run `wl-copy` off the UI thread.

### 2. The guard cannot see a build that starts and then fails (durability, small)

The guard treats a program that is missing or will not answer `ofolder version` as gone. A build that answers
`version` and then fails inside the portal still stops every file dialog (the side agent's note; recorded as an
expected failure in the suite).
**Do:** add `ofolder portal --check`, a dry run of the portal's startup (read the configuration, choose the
backend, check the bus name is claimable) that exits non-zero on any failure, and have both the guard and
`bin/install` call it instead of `version`.

### 3. Polling instead of events (performance, medium)

Per open dialog the release build uses about 3 to 5% of a core at rest (verified on the real desktop). The cause
is design, not a bug: a 150 ms docking loop forks `hyprctl clients -j` and parses it (app/strip_cmd.rs), a
200 ms poll forks `flea ipc` and scans `/proc`, and a 40 ms timer wakes the UI thread (about eight process spawns
a second per dialog; inference from reading the loops, the CPU figure is measured). On a desktop with many windows
the `clients` JSON grows.
**Do:** Hyprland has an event socket (`.socket2.sock`) announcing window move, close and focus, and a request socket
that needs no fork: use them behind the existing `Compositor` trait. Speak Flea 0.4's JSON-lines socket directly
instead of spawning `flea ipc`. For GTK and Strata use AT-SPI events instead of walking the tree. Expected result:
near-zero idle CPU, instant follow, and no hyprctl dependency for the hot path.

### 4. Privacy: what is kept, and how to forget it (privacy, small to medium)

ofolder keeps, in plain text and only locally: every folder and file confirmed in a dialog with the app that asked
(`recents.json`), window positions per app (`dialogs.json`), and the last 200 messages with paths
(`messages.log`, already `0600`). Observed: `recents.json`, `dialogs.json`, `favorites.json` and `settings.toml` are
created `0644` in `0755` folders; only `messages.log` is private. Your home is `0700`, so nothing is exposed today
(verified), but a backup tool, a changed home mode or a bind mount would change that.
**Do:**
- create all state files `0600` and folders `0700` with one shared helper (the code already exists in `core/messages.rs`);
- a "Forget recents" button and an expiry (for example 90 days) in settings; today the exclusion list is only in the TOML;
- **default exclusions** for sensitive folders (`~/.ssh`, `~/.gnupg`, the password-manager and wallet folders) so they are
  never recorded unless the maintainer removes the exclusion;
- show, in the settings Messages pane or doctor, exactly what is stored and where.

### 5. Writes: atomic, but not durable or race-free (durability, small)

Settings are written through a temp file, `fsync` and rename (good). Recents, dialog memory and favorites use a temp
file and rename without `fsync`, so a power loss can leave an empty file; and two dialogs open at once each read,
change and write the same file, so the later write silently drops the earlier one (inference from reading the code;
not reproduced).
**Do:** one `write_private_atomic(path, bytes, 0o600)` helper with `sync_all` for all of them, and an advisory
`flock` around read-modify-write for recents and favorites.

### 6. Guard watch is wider than it needs to be (security, small)

The guard's path unit watches the whole of `~/.local/bin`, so it runs on every change there (many tools write to it),
and each run executes the program named in the service file. Same-user only, so no privilege is gained, but it is more
triggering than needed.
**Do:** watch the program file and the portal configuration file themselves, and add `StartLimitBurst` so a fight with
another program that rewrites the chain on every launch cannot loop.

### 7. Identity of the asking application is a heuristic (privacy and correctness, design)

Most applications send no app id, so ofolder uses the class of the **focused window** when the request arrives
(`app/hooks.rs`). If focus changes in that moment, a recent or a start-folder rule is credited to the wrong app.
A start-folder rule only seeds a dialog that named no folder, and never overrides one, so the harm is limited
(tests cover this). Better signals are not available from the frontend (the caller is the portal, not the app).
**Do:** keep the heuristic, but record it as a limit, and show the app ofolder believes is asking in the Recents menu's
"This app" view so a wrong attribution is visible rather than silent.

### 8. Untrusted files are decoded in the strip process (security, medium)

Selected images and videos are decoded in the rails' own process. Good: dimensions are checked before decoding, a size
cap applies, work is off the UI thread, ffmpeg has a time limit and a `file:` input. **Correction (2026-11-03, checked
in the crate's source):** this review first said decoder memory limits were missing; the `image` crate already caps a
decode's allocation at 512 MiB by default. That limit is now stated explicitly in `strip/src/preview.rs`, with a side
limit of 30,000 pixels, and tested. Still true: ffmpeg and the SVG path run with the rails' full permissions, and image
and media decoders are a steady source of vulnerabilities.
**Do:** consider running thumbnailing in a short-lived child with `RLIMIT_AS` and a restricted filesystem view (landlock
or `bwrap`) later (medium).

### 9. Supply chain (security, small)

721 packages are locked, almost all through gpui. `cargo deny` is installed here, but there is no `deny.toml`.
**Do:** add one (advisories, the licence rule already in `AGENTS.md` that bans GPL/AGPL crates, duplicate and source
bans) and run it from `bin/canary` or weekly, since the advisory database needs the network and `bin/check` should not.

### 10. Dependence on undocumented interfaces (durability, ongoing)

Flea's picker contract (the `FLEA_PICKER` environment, `flea ipc`), Strata's accessibility labels and GTK's accessible
tree are all read, not documented. Today this is held by the end-to-end suite and `bin/canary` (they caught two real
breakages in one day). Not yet done: the held docs PR and issue to Flea; asking Strata for a stable chooser contract; a
known-good version table in the code so an untested version shows one line in the rails instead of failing quietly.

### 11. An unexplained flake (durability, unknown)

About one full end-to-end run in nine shows "Flea 0.4 `parent` ignored" or GTK "`find` Enter ignored". The suite now
prints the rails' own trail on failure. Until understood, treat it as a possible real intermittent command loss.

## Capabilities worth considering

Ordered by value for the cost. R-25 (folders of open file managers) is being spiked; R-71 (rename, trash) and the bar
widget are settled (later and no).

1. **A one-time first-run hint**, dismissible, saying what the two rails are. Nothing explains ofolder to a new user, and
   the user's reaction to the bar widget is the same lesson.
2. **Settings for what is TOML-only today**: start folders per app, excluded apps and folders, never-record paths.
3. **`ofolder doctor --report`**: a redacted text for a bug report (paths replaced), since support otherwise needs
   screenshots.
4. **A startup-latency check** in the suite. The requirement is under one second from dialog to rails; it is not measured
   today, only inferred from experience.
5. **Mutation testing on the logic crates** (`cargo-mutants` is installed) and a fuzz pass over the TOML, JSON and portal-
   file parsers, which take untrusted-ish text. Cheap and aimed at the code with the most branching.
6. **A keyboard and screen-reader audit of the rails** (R-05 is partly met; nothing was verified about assistive technology).
7. **Other compositors** (Sway, niri) behind the `Compositor` trait. Low priority: the target is Omarchy, which is Hyprland.
8. A resident helper instead of a process per dialog, only if the latency check shows startup is slow.

## Suggested order

1 (time limits), 2 (`portal --check`), 4 (private files, default exclusions, forget button), 5 (durable writes), then 3
(events instead of polling) as the larger piece, with 6, 8 and 9 alongside. Items 7, 10 and 11 are limits to write down and watch.
